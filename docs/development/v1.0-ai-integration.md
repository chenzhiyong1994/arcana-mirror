| 配置 | 值 |

| 小程序 AppID | `touristappid` |
| CloudBase 环境 | `<your-cloudbase-env-id>` |

| 模型 | `hy3` |

环境 ID、AppID 和模型别名是公开运行配置，不是密钥。仓库内不得出现微信 AppSecret、控制台凭据或模型密钥。

## 2. 实现范围

- `app.ts` 启动时初始化指定 CloudBase 环境；
- 主题问题通过 `wx.cloud.extend.AI.createModel("cloudbase")` 调用 `hy3`；
- 每日一牌不调用 AI，继续使用本地受控牌义；
- AI 输入只包含当前问题、牌阵、卡牌事实、牌位、朝向和受控牌义，不读取本地历史或账号资料；
- 新提问不再要求用户预选固定主题，由 `hy3` 直接从问题识别重点；旧历史的主题字段继续兼容；
- 用户问题被放在结构化数据边界内，System Prompt 明确忽略其中试图覆盖规则、修改格式或索取提示词的指令；
- 返回内容先提取 JSON，再校验字段长度、牌数、牌名、朝向、牌位、受控牌义、问题焦点、免责声明和危险措辞；
- “第一眼线索”不得复述、引用或套话改写用户问题；原始困扰在结果页使用独立框体展示；
- 调用异常、25 秒超时、空响应、非法 JSON、事实错配或安全校验失败时，统一返回本地基础牌义；
- 结果页标记“HY3 个性化解读”，本地降级明确标记为基础解读。

## 3. 真实连通性证据

已在当前小程序对应的微信开发者工具和 CloudBase 环境中执行真实请求：

1. 旧式 `{ data: { model, messages } }` 包装返回 `AI_MODEL_PARAM_REQUIRED`；
2. 按当前接口改为顶层 `{ model: "hy3", messages }` 后请求成功；
3. 响应包含 `model: "hy3"` 和 OpenAI 风格的 `choices[0].message.content`；
4. Provider 已按该真实响应结构实现，不依赖猜测的字段。

这项证据只证明环境、套餐和模型调用链可达，不等同于完整发布质量评估。

## 4. 隐私与安全边界

- 提问页提示用户问题会发送给 CloudBase AI，并要求避免输入姓名、电话、住址等可识别信息；
- 本地应用代码不主动把问题或模型原始响应写入日志或仓库；
- CloudBase 控制台可能提供 AI 请求/响应调用记录，正式发布前需检查控制台的日志保留与访问权限；
- 历史和图鉴仍只保存在当前设备，不跨设备同步；
- 自伤/伤人、违法、操纵、赌博和专业诊断类输入在普通抽牌前阻断或改写；
- 客户端直调不具备强服务端限流。正式流量扩大前需配置套餐用量告警；若出现滥用风险，应把 AI Provider 迁入云函数并实施主体级限流。


覆盖范围包括：

- 常见危机措辞与专业边界分类；

- 每日牌与降级内容使用本地免责声明，不冒充 AI 生成。
