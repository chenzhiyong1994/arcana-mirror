| 配置 | 值 |

## 2. 实现范围

- `app.ts` 启动时初始化指定 CloudBase 环境；
- 单牌/三牌通过 `wx.cloud.extend.AI.createModel("cloudbase")` 调用 `hy3`；默认生活指引不提交问题，固定生成财运、事业、爱情三向内容；
- 每日一牌不调用 AI，使用本地受控牌义和三条固定方向提示；
- AI 输入只包含解读方式、可选当前问题、牌阵、卡牌事实、牌位、朝向和受控牌义，不读取本地历史或账号资料；
- 具体问题不要求用户预选固定主题，由 `hy3` 直接从问题识别重点；旧历史的主题字段继续兼容；
- 用户问题被放在结构化数据边界内，System Prompt 明确忽略其中试图覆盖规则、修改格式或索取提示词的指令；
- 返回内容先提取 JSON，再校验字段长度、牌数、牌名、朝向、牌位、受控牌义、模式对应焦点/固定方向、免责声明和危险措辞；
- “第一眼线索”不得复述、引用或套话改写用户问题；原始困扰在结果页使用独立框体展示；
- 调用异常、25 秒超时、空响应、非法 JSON、事实错配或安全校验失败时，统一返回本地基础牌义；
- 结果页不展示模型或来源标签；真实 AI 与本地降级继续通过受控结构和安全校验保证可用性，娱乐性声明保持可见。

## 3. 真实连通性证据

已在当前小程序对应的微信开发者工具和 CloudBase 环境中执行真实请求：

1. 旧式 `{ data: { model, messages } }` 包装返回 `AI_MODEL_PARAM_REQUIRED`；
2. 按当前接口改为顶层 `{ model: "hy3", messages }` 后请求成功；
3. 响应包含 `model: "hy3"` 和 OpenAI 风格的 `choices[0].message.content`；
4. Provider 已按该真实响应结构实现，不依赖猜测的字段。

这项证据只证明环境、套餐和模型调用链可达，不等同于完整发布质量评估。

## 4. 隐私与安全边界

- 提问页提示用户问题会发送给 CloudBase AI，并要求避免输入姓名、电话、住址等可识别信息；
- 本地应用代码不主动把问题或模型原始响应写入日志或仓库；
- CloudBase 控制台可能提供 AI 请求/响应调用记录，正式发布前需检查控制台的日志保留与访问权限；
- 历史和图鉴仍只保存在当前设备，不跨设备同步；
- 自伤/伤人、违法、操纵、赌博和专业诊断类输入在普通抽牌前阻断或改写；
- 客户端直调不具备强服务端限流。正式流量扩大前需配置套餐用量告警；若出现滥用风险，应把 AI Provider 迁入云函数并实施主体级限流。

## 5. 自动化验证

运行：

```powershell
npm run typecheck
npm test
```

覆盖范围包括：

- CloudBase 消息构造、JSON 提取和真实响应字段映射；
- 单牌/三牌事实一致性、无问题生活指引、三项固定方向、问题聚焦与摘要去复述契约；
- 常见危机措辞与专业边界分类；
- Provider 超时、非法结构和不安全输出的本地降级；
- 每日牌的三项固定方向与降级内容使用本地免责声明，不冒充 AI 生成。

## 6. 微信审核名称与简介

2026-07-28 根据本次实际审核反馈，公众平台对外品牌由原名称调整为“心镜拾光”。“阿卡纳”及其近似写法不得再用于小程序名称；公众平台简介不得使用容易被理解为提供占卜或未来预测服务的表述。

提交时统一使用：

| 字段 | 内容 |
| --- | --- |
| 小程序名称 | 心镜拾光 |
| 界面英文标识 | MIRRORLIGHT |
| 小程序简介 | 通过图像卡片与 AI 文字整理，帮助用户梳理当下困扰、获得新的观察角度，并保存反思与行动记录。内容仅供娱乐和自我反思，不构成专业建议。 |

采用这套文案的原因：

- 名称保留“心镜”的自我观照语义，与现有古镜 Logo 和界面视觉一致；
- 简介直接列出图像卡片、AI 文字整理、反思与行动记录三个实际功能点，避免空泛宣传；
- 名称、简介与首页实际功能保持一致，不承诺结果准确性，不把卡片当作事实来源；
- “阿卡纳”限制来自本次具体审核反馈，不把它误写成公开规范中的通用禁词；
- 名称是否被占用只能以微信公众平台提交页面的实时校验为准，公开网页搜索不能替代该检查。

注意：调整名称与简介不能掩盖实际服务。若审核仍将随机翻牌与情境解读判定为平台不接入的测试或迷信类内容，需要依据新的驳回理由调整真实功能、类目或上线范围，而不是继续替换同义词。
