# 阿卡纳心镜：长程开发执行基线

> 基线日期：2026-07-19
>
> 状态：本地 MVP 功能闭环已完成
> 用途：本文件记录当前阶段的唯一执行顺序和范围；产品长期方向仍由 PRD 与技术架构描述。

## 1. 当前目标

先在微信开发者工具中完成可独立运行、可完整测试的本地 MVP。当前阶段不接入 CloudBase、真实 AI、微信云身份或账号系统，使用微信小程序本地存储与模拟解读跑通完整功能闭环。

高保真视觉和精细交互由独立 Agent 负责；本阶段只提供清晰可用的低保真页面、稳定页面状态和可替换的数据接口。

## 2. 本地 MVP 范围

### 必须完成

- 22 张大阿尔卡那受控数据、单牌抽取和正逆位；
- 每日一牌：按 Asia/Shanghai 业务日期唯一，重复进入复用原结果；
- 主题、问题输入和确定性安全分类；
- 建议改写、专业边界、危机阻断和滥用阻断；
- 与未来真实 AI 共用结构契约的模拟解读；
- 可切换模拟成功、超时、非法结构和不安全输出；
- AI 模拟失败后的受控模板降级；
- 主题解读由用户明确选择是否保存到本地历史；
- 历史列表、详情、原问题折叠、单条删除和清空；
- 设置页中的模拟 AI 标识、娱乐性说明和本地数据说明；
- 类型检查、领域单元测试、契约测试和微信开发者工具编译验收。

### 当前不做

- 日记、心情、自由笔记或可编辑行动；
- CloudBase、云函数、云数据库和真实 AI；
- 微信云身份、显式登录、用户名或密码账号；
- 本地历史自动迁移到云端；
- 三牌、回访、牌库浏览页和分享图；
- 高保真视觉、复杂动效、声音和震动；
- 支付、社区、运营后台或多端同步。

## 3. 本地历史规则

1. 每日牌自动持久化，以保证当日唯一和退出恢复。
2. 主题解读默认不进入历史；只有用户明确点击“保存到历史”才持久化。
3. 未保存的主题解读仅存在于当前本地流程，退出后清理。
4. 历史数据存储在微信小程序本地存储沙箱，只在当前设备与当前小程序内可用，不跨设备同步。
5. 历史包含 Reading 时间、类型、主题、问题、卡牌、朝向、结构化解读和结果来源，不包含日记字段。
6. 用户可单条删除或清空全部本地记录。

当前调用关系：

```text
页面 → ReadingService → LocalReadingRepository → wx 本地存储
                      → MockInterpretationProvider
```

未来接入云端时只替换 Repository 与 Provider，不改页面和领域契约。CloudBase 阶段可使用云函数上下文 OpenID 校验云端数据归属，但不建设显式账号系统。默认不自动迁移现有本地历史。

## 4. 工程边界

- 卡牌事实、状态迁移、安全分类和降级组合写成纯 TypeScript；
- 页面不直接调用 `wx.setStorage`，统一依赖 Repository；
- 页面不直接拼模拟文案，统一依赖 `InterpretationProvider`；
- 模拟异常通过仅开发环境可见的设置控制；
- 模拟 AI 返回值必须经过与未来真实模型相同的 Schema 和牌面事实校验；
- 本地随机只用于功能开发，未来云端接入后由服务端安全随机固化最终事实；
- 私密问题不进入日志、测试夹具或仓库。

- 模拟 AI 和未来真实 AI 共用结构化 Schema；
- 页面与本地存储、模拟 Provider 解耦；
- 类型检查、领域测试和契约测试全部通过；
- 仓库不包含真实密钥、私人问题或模型原始响应。
