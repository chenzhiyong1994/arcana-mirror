# 心镜拾光：PRD 自检与修订报告

> 历史说明：本文件记录 PRD v0.1/v0.2 的审查结果。项目作者随后决定先完成本地存储 + 模拟 AI 的功能闭环，并移除日记；当前执行顺序与范围以 `07-execution-baseline.md` 和 PRD v0.3 为准。

## 0. 产品定型

| 维度 | 结论 |
| --- | --- |
| 商业属性 | 个人自研、非商业化；按自研项目检查投入产出，不检查商业售卖模型 |
| 功能类型 | C 端工具型软件 |
| 文档范围 | 0-1 完整 MVP |
| 审查强度 | 完整审查，但降低 B 端组织、复杂 RBAC、多租户和商业运营要求 |
| AI 功能 | 适用；情境化解读、安全分类和降级是核心 |
| 审查材料 | 产品定义、MVP PRD、技术架构、开发路线、Claude Opus 4.8 审查记录 |

## 维度01 - 业务分析质量 ｜ 评级：合格

### 具体发现

1. **背景、目标和替代方案已说明**：第1—3章解释了为什么不做普通在线抽牌，以及个人作品集目标如何影响范围。
2. **决策依据可追溯**：同类产品参考与合规资料已进入产品定义和 PRD 第9章。
3. **仍缺真实用户证据** [P2]：当前用户画像和场景来自案头分析，尚无访谈或可用性测试。最小改进是在原型后完成 3—5 位体验者任务测试，并记录原始证据与结论差异。

### 隐性问题推断

测试者可能因认识开发者而给出礼貌性反馈。内测问题应围绕具体任务完成和误解点，而不是只问“喜不喜欢”。

## 维度02 - 产品类型适配性 ｜ 评级：优秀

### 具体发现

1. **工具型定位清晰**：功能围绕短路径、自助使用和个人历史，没有引入审批、复杂权限或交易。
2. **载体匹配场景**：微信小程序适合低频、轻量、无需安装的使用方式。
3. **部署决策已收敛**：Claude 审查后锁定 CloudBase 单路径，PostgreSQL 仅为 P2 迁移练习，避免过度架构。

### 隐性问题推断

如果后期加入大量剧情、成长或卡牌收集，应重新判断是否已从“工具型小程序”变成“小游戏”，不能在同一架构上无边界叠加。

## 维度03 - 产品定位合理性 ｜ 评级：优秀

### 具体发现

1. **一句话定位完整**：明确成年用户、困扰整理、自我探索和微行动价值。
2. **做与不做边界明确**：不预测确定未来、不替代专业意见、不做真人、支付、社区和改运服务。
3. **差异化能落到功能**：问题改写、结构化解读、微行动、日记和回访均可追溯到“自我探索闭环”。

### 隐性问题推断

产品名称和宣传文案若重新使用“精准占卜、预测未来”等表达，会推翻当前定位并放大平台风险，因此命名应作为上线审核门禁。

## 维度04 - 场景分析与用户旅程 ｜ 评级：合格

### 具体发现

1. **核心场景完整**：每日牌、主题困扰和回访均用人物、时间、地点、起因、经过、结果描述。
2. **异常旅程已进入主流程**：改写、专业边界、危机阻断、AI 降级和失败恢复不是附录，而是流程分支。
3. **MVP/P1 表述需在原型同步** [P2]：PRD仍描述回访场景，但回访已降为 P1。原型第一轮应明确不把回访当作 MVP 验收阻塞项。

### 隐性问题推断

用户可能在公共场所打开历史详情，原问题默认折叠是必要设计；原型还需验证折叠状态、系统截屏和分享预览是否泄露内容。

## 维度05 - 文档结构完整性 ｜ 评级：优秀

### 具体发现

1. **14章结构齐全**：元信息、版本记录、背景、目标、范围、风险、功能、埋点、权限、发布和待决均已覆盖。
2. **框架和细节分离合理**：产品定义、PRD、技术架构和路线图各自承担单一职责，并由索引连接。
3. **版本管理已建立但需持续维护** [P3]：Claude 修订后 PRD 修改记录仍为 v0.1，下一轮确认技术 Spike 后应更新为 v0.2 并记录关键变更。

### 隐性问题推断

后续原型和工程实现应引用需求编号或验收用例，避免文档更新后实现无法追溯。

## 维度06 - 架构设计质量 ｜ 评级：合格

### 具体发现

1. **模块化单体符合项目规模**：没有微服务、队列、Redis、向量数据库等非必要组件。
2. **信任边界和降级清晰**：客户端不可信，服务端固化抽牌，LLM 是外部依赖，日志不充当私密数据旁路。
3. **CloudBase 能力需 Spike 验证** [P1]：事务、条件更新、幂等唯一性、定时触发和目标模型地域可达性仍是 go/no-go，不应在验证前开始完整页面开发。

### 隐性问题推断

单一 `api` 云函数可减少部署复杂度，但 action 路由、依赖初始化和包体积需要约束；否则会演变成巨型处理器。

## 维度07 - 数据建模质量 ｜ 评级：合格

### 具体发现

1. **核心实体关系完整**：用户、牌组、牌、牌阵、Reading、抽牌事实、解读、日记、回访、Prompt 和安全决定均有关系。
2. **生命周期字段已补齐**：Claude 审查后增加 `expire_at`、`deleted_at` 和 CheckIn `updated_at`。
3. **实际存储保护级别诚实**：字段使用中性命名，字段级加密未被伪装为已实现能力。

### 隐性问题推断

CloudBase 实际集合设计可能选择内嵌 ReadingCard，与关系型 ER 不完全一致。实现 ADR 应记录物理模型差异、索引和单文档大小约束。

## 维度08 - 流程与角色设计 ｜ 评级：优秀

### 具体发现

1. **正常和异常路径闭环**：从创建、抽牌、生成、降级、保存到删除均有状态和操作说明。
2. **并发幂等得到补强**：`reading_id + prompt_version` 条件抢占 Generating，避免重复模型调用。
3. **角色边界匹配个人项目**：只有体验用户和开发者，不引入无价值的复杂 RBAC；同时没有夸大云管理员不可访问数据。

### 隐性问题推断

`FallbackCompleted/Failed → Generating` 的“一次重试”已通过持久化 `ai_retry_count` 与原子条件更新约束，不能退化为仅靠客户端按钮隐藏。

## 维度09 - 交互设计质量 ｜ 评级：待改进

### 具体发现

1. **页面状态覆盖充分**：loading、empty、error、blocked、fallback 和删除确认均已规定。
2. **组件级细节仍不足** [P1]：尚未产出页面线框，抽牌页的手势、可跳过动画、返回确认、结果页展开方式和长文本滚动需要在原型中明确。
3. **无障碍方向已提出但未验证** [P2]：减少动态效果、声音/震动开关进入文档，但还没有触控尺寸、对比度和读屏标签标准。

### 隐性问题推断

神秘氛围容易导致低对比度、小字号和过长动画。视觉设计必须服从可读性与流程效率，而不是只追求“玄学感”。

## 维度10 - 商业分析深度 ｜ 评级：不适用

本项目明确非商业化，不检查市场规模、收入模式、CAC、LTV 和付费转化。替代检查如下：

1. 已估算约 80 小时首版预算；
2. 已将学习收益和作品集产出定义为主要回报；
3. 已设置范围熔断，避免为展示复杂度而堆叠组件。

## 维度11 - MVP 策略与演进蓝图 ｜ 评级：优秀

### 具体发现

1. **审查后边界更可执行**：单牌为 MVP；三牌、回访、完整埋点、自动 E2E 和 40+ 评估集进入 P1。
2. **MVP 仍保持完整闭环**：提问、安全、抽牌、AI/降级、日记、历史和删除均保留。
3. **削减顺序明确**：任何阶段超期一周或总投入接近 80 小时，立即停止 P1 并进入稳定收尾。

### 隐性问题推断

如果模型 Spike 失败，应优先交付静态/模板解读版本，而不是无限期寻找模型；它仍可以展示领域规则、状态机、隐私和小程序工程能力。

## 维度14 - 运营方案与效果跟踪 ｜ 评级：合格

### 具体发现

1. **符合非商业项目**：发布按本地、开发、内测、体验和作品集分阶段，不建设客服与增长运营。
2. **小样本目的表述正确**：5位体验者用于发现问题，不用于证明市场需求。
3. **最小指标与完整埋点已区分** [P2]：MVP只保留故障定位日志，完整行为埋点进入 P1；内测需使用任务记录表补足定性证据。

### 隐性问题推断

项目结束后若只展示漂亮页面而不展示失败率、降级案例和范围取舍，会损失最有价值的作品集证据。

## 维度12 - 异常处理与健壮性设计 ｜ 评级：优秀

### 具体发现

1. **异常覆盖广**：弱网、重复点击、AI 超时、非法结构、不安全输出、登录/身份、删除失败、Prompt 注入和静态资源失败均有处理。
2. **删除机制已从承诺变为组件**：定时清理函数负责 `deleted_at/expire_at` 物理删除与失败重试。
3. **仍需定义真实恢复指标** [P2]：Spike 后补充模型硬超时、重试次数、临时数据保留期和清理告警阈值。

### 隐性问题推断

云函数重试可能造成至少一次执行语义，抽牌和解释写入必须通过条件更新与幂等记录抵御，而不能只禁用前端按钮。

## 维度13 - AI 功能设计质量 ｜ 评级：合格

### 具体发现

1. **AI 价值与边界明确**：AI 只做主题问题的情境组织；每日牌不调用 LLM；用户保留判断权。
2. **可靠性体系完整**：Prompt 分层、Schema、语义一致性、确定性安全规则、增强分类、降级和版本记录相互配合。
3. **供应商与安全仍需实测** [P1]：境内模型的可达性、中文 Schema 稳定性、Prompt 注入抵抗和危机资源均需在发布前用真实评估验证。

### 隐性问题推断

“模型返回 JSON”不等于内容正确。评估报告必须分开呈现结构合格、牌面一致、安全合规和主观有用性，不能合成一个模糊准确率。

## 最终汇总

### 重大风险项

| 风险项 | 结论 |
| --- | --- |
| R1 产品定位缺失 | 不存在 |
| R2 核心流程缺失 | 不存在 |
| R3 数据模型严重缺陷 | 不适用；工具型产品关键数据结构已覆盖 |
| R4 角色权限完全缺失 | 不存在 |
| R5 功能存在致命断裂 | 修订后未发现 |
| R6 需求与目标脱节 | 不存在 |
| R7 合规风险 | 已识别；真实审核前仍需复核平台规则和危机资源 |
| R8 SaaS 无多租户 | 不适用 |

### 问题清单

#### P0

无。

#### P1：开发前/发布前必须解决

1. 完成 CloudBase + 境内主/备模型 go/no-go Spike；
2. 用原型明确核心页面组件和返回/失败交互；
3. 确认牌面视觉资产授权或原创方案；
4. 外部预览前核实高风险场景使用的本地紧急资源与平台审核口径。

#### P2：迭代中补齐

1. 完成 3—5 位体验者的任务测试，替代泛化满意度询问；
2. Spike 后写入真实超时、保留期、告警和性能阈值；
3. 在物理数据模型 ADR 中记录 CloudBase 集合、索引和内嵌结构；
4. 建立触控尺寸、对比度、读屏标签和减少动态效果检查表。

#### P3

1. 技术 Spike 后更新 PRD 版本和变更记录；
2. 后续需求、原型、测试和代码使用统一编号建立追溯关系。

### 亮点

- 主动将产品从“预测未来”转为“开放式自我探索”，产品和平台边界一致；
- 将每日牌与 AI 主题解读拆开，降低成本和不必要风险；
- AI 不可用时仍有完整降级体验；
- 把隐私删除、日志脱敏、模型版本和离线评估放入首版架构；
- 经过 Claude Opus 4.8 审查后删除双后端路径和过量 P0，显著提升完成概率。

### 综合建议

材料已经足以进入技术 Spike 和低保真原型，不建议继续扩写文档。下一步最先验证模型可达性、CloudBase 事务/幂等和定时清理；验证通过后冻结 ADR，再开始页面与工程实现。
