# 心镜拾光：开发路线与作品集计划

## 1. 当前路线原则

- 当前阶段是 v1.1 完整牌组候选，目标是完成微信审核前门禁；
- 前端采用“黑金典藏 · 镜廊仪式”高保真视觉，优先保证卡牌可读、流程顺滑和移动端性能；
- Reading、历史和图鉴继续使用本地 Repository；主题解读已通过 Provider 适配器接入 CloudBase AI `hy3`；
- 日记、心情、自由笔记和可编辑行动不在产品范围内；
- 安全分类、结构校验、失败降级、历史删除和自动化测试属于 P0；
- 不引入显式账号和云端历史；后续若需要更强限流，再把 AI 调用迁入云函数；
- 不建设签到、回访或连续使用循环，新增惊喜应在单次使用中直接可感知。

## 3. 本地 MVP 功能范围

### P0：本轮闭环

- 每日一牌：按 Asia/Shanghai 自然日唯一，首次抽取后自动进入本地历史；
- 主题提问：5—200 字，由模型直接根据问题识别重点，不要求用户先选固定类别；
- 输入安全：允许、建议改写、专业边界、自伤/伤人阻断、操纵/违法阻断；
- 单牌抽取：78 张完整牌组、正逆位、单次抽取结果固定；
- AI 解读：CloudBase 内置 Provider `cloudbase` 调用 `hy3`，输出为聚焦当前问题的结构化建议；
- 输出校验：字段、长度、牌面、朝向、固定免责声明与不安全措辞；
- 失败降级：任何 Provider 异常或输出不合规都返回受控基础牌义；
- 本地历史：每日牌与完成的主题解读自动保留最近 30 条；
- 历史管理：详情、单条删除和清空全部；
- 设置说明：明确 CloudBase AI、本地数据、无账号边界和敏感信息提示；
- 自动化验证：领域、安全与结构契约测试。

- 图鉴收集：实际翻牌解锁、正逆位进度、翻牌次数和 22 张总览；

## 4. v1.1 验收路径

1. 每日一牌：首次抽取生成记录，同一天再次进入复用同一个 Reading；
2. 正常主题：安全检查通过，从 78 张抽牌，`hy3` 返回合规结果并自动出现在最近记录；
3. 三牌主题：三张互不重复，可分别出现大/小阿尔卡那和正逆位；
4. 改写主题：确定性预测或专业问题先显示受控改写，采用后继续；
5. 高风险主题：危机、自伤伤人、操纵、违法或赌博在抽牌前阻断；
6. 降级主题：断网、超时、非法结构或不安全输出均得到对应牌的基础牌义降级；
7. 图鉴与包体：五组 78 张路径有效，主包和 `deck` 分包均低于 2 MiB；
8. 数据管理：每日牌与主题结果自动保留最近 30 条，历史可单删，设置页可清空全部。

v0.1 详细操作见 `docs/development/local-mvp-validation.md`；v0.2 三牌与图鉴复验见 `docs/development/v0.2-validation.md`；v0.3 体验验收见 `docs/development/v0.3-validation.md`；v1.0 AI 与发布门禁见 `docs/development/v1.0-ai-integration.md`；v1.1 完整牌组合同见 `docs/product/10-v1.1-complete-78-card-deck.md`。

## 5. 未来替换边界

页面依赖 `ReadingService`，领域服务依赖 `ReadingRepository` 与 `InterpretationProvider`。v1.1 只扩展 Card 数据、牌面资源和页面分包，没有改动 Reading、正逆位、保存规则或 AI 安全边界。

云端历史若启用，可使用云函数上下文中的 OpenID 做数据归属，但这不等于建设用户名/密码账号系统。本地历史是否迁移到云端必须另行设计，当前默认不迁移。

## 6. 质量门禁

| 门禁 | 当前阶段标准 |
| --- | --- |
| 工程 | TypeScript 类型检查通过，微信开发者工具能加载主包和 `deck` 分包 |
| 领域 | 每日唯一、78 张牌可达、三牌不重复、显式保存、删除与清空符合规则 |
| 资产 | 22+56 张牌面齐全，四花色各 14 张，路径、尺寸、联排与包体校验通过 |
| 安全 | 高风险输入在抽牌前阻断，模型式输出失败后不直接展示 |
| 数据 | 无密钥、无账号；历史只在本地；问题会发送给 CloudBase AI，常规应用日志不主动记录原文 |
| 降级 | timeout、invalid、unsafe 与调用异常均返回受控结构 |
| AI | 40 条发布评估覆盖单牌、三牌、边界、高风险和 Prompt 注入 |
| 范围 | 无日记字段、云端历史、隐式账号或留存型循环 |
